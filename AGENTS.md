# Squish - working rules

`docs/SPEC.md` is the build contract for behavior (CLI flags, mode semantics, JSON shape). This
file is for gotchas that aren't about behavior - build environment and licensing traps that are
easy to reintroduce without realizing it.

## Command Line Tools only - there is no Xcode here

`xcode-select -p` on the reference development machine points at
`/Library/Developer/CommandLineTools`, not an `Xcode.app`. There is no `.xcodeproj`, no
`xcodebuild` anywhere in the build pipeline, and `scripts/build-app.sh` assembles `Squish.app` by
hand (writes `Info.plist`, copies binaries, `codesign --sign -`) instead of using an Xcode build
system. Don't add a dependency, SwiftPM plugin, or build step that assumes Xcode is installed -
`swift build` needs to keep working from Command Line Tools alone.

## `vendor/bin` and `vendor/lib` are gitignored build products - not missing files

A fresh clone has an empty `vendor/`. That's intentional (see `.gitignore` and
`CONTRIBUTING.md`), not a broken checkout - `./scripts/vendor-codecs.sh` populates both
directories from Homebrew formulas, and `.build/` needs a full `swift build -c release` the same
way. If `squish` or `Squish.app` can't find an encoder, that's the first thing to check, not a
sign something is wrong with the source tree.

## Watch `vendor-codecs.sh`'s perceptual-metric fallback - it can silently change what license
## Squish is shipping

`vendor-codecs.sh` tries, in order: (a) the `ssimulacra2` tool bundled in the `jpeg-xl` Homebrew
keg (BSD-3-Clause), (b) `cargo install ssimulacra2_bin` (same license), (c) a from-source libjxl
build (not automated, documented dead code path), (d) `dssim` via Homebrew
(**AGPL-3.0-or-later**). Step (d) only triggers if both (a) and (b) fail on the machine running
the script, and it only prints a log line - it doesn't fail the build or ask for confirmation.
That means a build on a machine where the `jpeg-xl` keg happens not to ship `ssimulacra2`, or
where `cargo` isn't set up, can ship an AGPL binary that a build on a different machine wouldn't.
Check the script's own log output (`shipped metric binary: ...`) before treating a build as
release-ready, and see `ATTRIBUTION.md`'s "dssim" section for what shipping it would actually
require.

## `pngquant` is GPL-3.0-or-later - don't swap codecs without checking `ATTRIBUTION.md` first

`vlossless` mode's PNG path depends on `pngquant`, which is GPL-3.0-or-later (Homebrew's own
formula metadata confirms this: `GPL-3.0-or-later AND HPND AND BSD-2-Clause`). That's a deliberate,
documented tradeoff, not an oversight - see `ATTRIBUTION.md` for the full reasoning and what it
requires of anyone distributing a build. If you're adding or swapping a vendored codec, check its
license against that file's summary table before wiring it in; the project has stayed accidental-
copyleft-free everywhere except pngquant, and it should stay that way on purpose, not by luck.

## Never commit `vendor/bin`, `vendor/lib`, or `tests/fixtures/`

All three are `.gitignore`d for the same reason: they're regenerated by a script
(`vendor-codecs.sh` / `make-fixtures.sh`), not authored, and the vendor directories specifically
contain third-party compiled binaries that don't belong in this repo's git history even if
someone's local `git add -A` habit would otherwise sweep them in.

## The app is ad-hoc signed only - don't assume a downloaded build just opens

`Squish.app` has no Developer ID signature and is not notarized. A build works fine on the
machine that built it, but a copy downloaded onto a different Mac triggers Gatekeeper's "cannot
be opened" or "is damaged" dialog, and needs right-click → Open on first launch. See `RELEASE.md`
for the full explanation and what proper distribution would require. Don't write install
instructions, QA scripts, or release notes that assume a plain double-click works for anyone
other than the person who built it.
